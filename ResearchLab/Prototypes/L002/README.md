# L002 | Governor and construction observation
Research-only, no menus, action calls, save keys or explicit campaign state writes. Subscriptions: session/load, daily event, governor and building-level changes. Reads actual active model values and native identities, records market gold separately from construction reserve; at most 24 player-clan holdings per snapshot and 1200 log rows per behavior lifetime. Calls into active model getters; provider purity and callback order require native testing. Daily snapshot order relative to other events not assumed. Local private per-session log under LocalAppData/BannerlordResearchLab. Source not installed. 
Control test (separate authorization): disposable official Sandbox profile, own one castle/town, keep no governor for 3 campaign days, assign an eligible governor via native UI, record arrival, model effects, and 3 daily observations, use native reserve controls once, verify market balance vs reserve and construction progression, remove or replace governor via native UI, compare, save quit reload. No automatic changes. Use same building, no siege, compare confounders such as loyalty, prosperity, project, food, perks and time; do not infer causality from a changing daily total. Test real governor arrival rather than assuming appointment equals presence. No production integration or release. If observations support an actual family/service choice, design a separate gameplay prototype only after review.

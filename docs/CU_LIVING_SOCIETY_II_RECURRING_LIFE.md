# Living Society II: recurring activities, independent persons and native folios
24 November 2026. Follow-up to draft PR #96 and CU_SEVEN_CAREER_SOCIETY_FOUNDATION.md. The seven top-level careers are final. No additional careers, no changes to guided start rules, no new framework, no forced title or career changes.

## Q1: recurring life activities
Implemented source increment: existing career chronicle and household camp expose a voluntary recurring review. A new versioned CU_CAREER_REVIEWS_1 receipt stores hero ID, recorded career, last observed day and count. The corresponding save key CU_recurring_career_reviews_1 is independent of all existing records. A valid review requires actual current native/provider evidence, a living active non-captive player, no map encounter or sea travel, at least seven campaign days since the previous review for the same hero/career, and a bounded record set (64). The count is not tenure, wages, achievement, promotion or proof that the duties were fulfilled. A missing legacy save key means no historical review receipts. Keep old career chapters and native life histories unchanged. If a saved starting role no longer matches the current situation, reject unsupported evidence rather than auto-changing role. Career transitions remain a separate episode-history milestone.

Career-specific longer loops and events below are future designs, not implemented quests:
- Wanderer: town livelihood review, native trade/craft/work outcomes, patron introduction, family assistance, travel; weekly planning, optional meetings and observed earnings. Events: livelihood setback, invitation to service, family request. Native gold, inventory and quests remain authority.
- Outlaw: review actual independent band strength, provisions and safety; contact members, weigh loyalty, negotiate restitution or leave crime. Events: lost followers, scarcity, opportunity for lawful employment. Fourberie/native owns crime, hiding, pursuit and amnesty. No criminal classification merely from party size.
- Mercenary: review active contract, native company payroll and readiness; seek employer or renew only via actual contract. Events: losses, contract expiration, refusal to renew, rival offers. No parallel payroll or generated contracts without native support.
- Soldier: review actual supported SaS snapshot, host presence, rank and duty; existing provider handles training, promotion, pay, discharge and leave. Events: rank changes, patron changes, capture and uncertain provider state. No pretend enlistment from party location or receipt.
- Knight: current oath and patron review; existing 30-day muster/final seven-day window, escort and orders. Events: breach, captive patron, succession requiring consent, recognition petition. A review never completes a muster or escort.
- Lord: review native non-ruling landed clan leadership; actual household appointments, estate accounts, audiences and inheritance discussions. Events: estate loss, family conflict, petition for assistance, appointment vacancy. Improved Garrisons owns automated training/recruitment and transfers remain guarded.
- King: review current native ruler status; council, actual appointments and recorded claims. Events: heir question, court petition, loss of crown, successor. Diplomacy/native owns kingdom policy, votes and wars. No parallel crown succession.

Frequency: weekly personal review; native event-driven stories on actual changes; existing per-person family cooldown 30 days; knight muster as existing; NPC requests as existing quotas. Future actions need separate eligibility, consequence, rejection, exact native action/provider ownership and tests. No forced task spam or universal conquest goal.

## Q2: independent NPC life
Implemented source: NPC initiative candidate order is now fewest prior requests, then oldest last request, then stable ID. Duplicate candidates removed; existing co-location, adult, active, non-captive, cooldown, memory and one-pending rules remain. Failure to propose no longer stops the remaining candidates. Native reciprocal marriage links observed for known people (including two NPCs) are recorded once per pair, with no assumed ceremony date. Existing directed bonds remain for both tracked people. A saved historical bond is not the current spouse. This is observation, not an autonomous marriage engine.

Next design: extend the existing known-person system, initially a bounded group of active adults, not all native heroes. A personal initiative has actor, target, goal, source, relevant traits, current wealth and obligations, and expiry. NPC-to-NPC patronage, friendship, reconciliation or household cooperation begins as a proposal; eligibility includes actual presence, active status, life, adulthood, non-captivity and no invalid native relationship. Both parties must have compatible needs and willingness; refusal, postponement or consent recorded separately. Candidate order deterministic and bounded, one proposal per person per interval, no repeated rewards. Modeled intention is not native dialogue. Observe actual native changes and retain evidence. Use only the verified native marriage/relationship model or approved adapter for any actual marriage or relation mutation; do not assign spouse fields or fabricate family links. Do not create autonomous marriages until explicit eligibility, consent, existing spouse, age, kinship, native model availability and save/load tests pass. Native births/deaths and clan ownership remain authoritative. Conflicts are personal disagreements and possible petitions, never competing war/faction/crime AI. No remote party control.

## Q3: native-style interface and dynasty history
Existing CUNobleDossierScreen and CUHouseholdCampScreen stay in place. No new overlay, asset, input hook or mission. Implemented source: eligible native person inspection shows current reciprocal spouse separately from past links, modeled ambition and prior support/refusal, and up to five newest saved events involving that person's native Hero ID. Household camp member inspection displays the same filtered personal history; chronicle includes the player's own recent records. Record kinds and detail are shown as recorded; no invented dates, quotes or causal claims. The existing bounded life ledger is not a complete multigenerational archive.

Proposed information architecture:
- Character folio: native portrait and identity; age, culture, current clan, career/calling, actual political standing, property, relationship, current verified spouse, parentage; modeled ambition clearly labeled; personal duties and available actions.
- Household folio: real roster, residence evidence, officers and their actual vs personal roles, children/education, resource summary, correspondence, service review. Buttons use existing native menus and recheck action eligibility.
- Dynasty folio: actual family tree and verified parentage, deceased and living members, current native succession distinct from modeled claims, career episodes and historical deeds. Persistent per-person archive will preserve important events while retaining bounded recent history. Current five-event view is not a complete archive.
- Layout: existing native-style Gauntlet art and portrait pipeline; native typography, consistent left navigation and readable right detail area. Back/Escape, focus, scroll, 16:9 and ultrawide, 3 resolutions, CustomisableUI and Diplomacy coexistence. Read-only information must not trigger game mutations. No new screenshots or visual acceptance claimed.

# v0.52 | Native household development and story presets

**User-observed defects (November 19, 2026):** at least one generated adult offspring has zero attributes or skills, wives and children have repeated personality traits, and family members start with relation near 1. The user requests selectable household stories, inherited personality variation and age-based upbringing.

## Presets

| Household story | Generated spouse | Child default upbringing | Starting relation range, approximately |
|---|---|---|---|
| Natural | independent, varied traits | Independent | spouse 46–58, children 42–58 |
| Honorable | Honor 2; Mercy/Generosity often high | Kind (Mercy favored) | spouse 69–81, children 62–78 |
| Martial | Valor favored | Martial | spouse 49–61, children 40–56 |
| Scholarly | Calculating favored | Scholarly | spouse 56–68, children 47–63 |
| Mercantile | Calculating favored | Mercantile | spouse 49–61, children 42–58 |
| Strained | Generosity sometimes negative | Independent | spouse 6–18, children 7–23 |

Each child can override `FamilyTradition` with `Kind`, `Martial`, `Scholarly`, `Mercantile`, or `Independent`. A chosen household story never forces a specific child count, spouse background, or children's names.

## Generated Hero policy

- Use native `HeroDeveloper.AddAttribute` to raise any missing attributes to at least 2 for newly generated **adults**; never lower native attributes.
- Use native `HeroDeveloper.SetInitialSkillLevel` on age-appropriate training skills (six per upbringing). Require three positive skills and all six positive attributes for an adult. Log actual counts and fail visible startup contracts on unrealizable results.
- Only adjust the five game personality traits: Mercy, Valor, Honor, Generosity, Calculating. Use independent per-Hero random draws, with 50% parental inheritance, 30% upbringing influence and 20% independent variation in the core policy. Distinguish any otherwise identical siblings. Do not alter existing NPC donors or the player.
- `Honorable` spouse receives Honor 2. Children with `Kind` upbringing receive at least Mercy 1, with different other traits. Native traits remain capped to valid game levels.
- Establish each new spouse/player and parent/child pair through the native `Hero.SetPersonalRelation` API. Vary targets by scenario and per family member. Emit requested/effective/reverse relation values, as the real DiplomacyModel can modify the displayed value.
- After creation, register the 0–6 offspring's Hero IDs and upbringing in the real campaign behavior. Save a single compact primitive string through `IDataStore.SyncData`, not an unregistered save class. At milestones ages 6, 10, 14 and 18, nudge a matching personality trait and top-up suitable native training without erasing the game's education choices. Save milestones to prevent duplicate grants after reload. Real born-after-start children are excluded.

## Known boundaries

This does **not** retroactively rebuild attributes or personalities of heroes generated by older versions in existing saves. That would require an explicit, user-authorized migration with a separate safety audit. All new startup family changes occur only on newly generated characters. The campaign milestone records persist after saving, but actual save/reload integrity remains a live-game acceptance gate.

The native Story/Banner/FaceGen stages and the v0.51 age UI are unchanged. Scenario choices reuse the working chapter-style House field editor. The 5-game-trait set does not include custom virtues or invented engine skills.

## Release gates

1. Compile against pinned native 1.5.7.125802 references with zero warnings and errors. All C# and source contracts must pass.
2. In one clean new Sandbox, choose Honorable story, spouse 48, Lord 50, children [25,22,20,18,16,15], and select one Martial and one Scholarly upbringing. Verify six children and nonzero skills/attributes on every adult, Honor 2 wife, Mercy-positive Kind children, different personalities, and explicit relations in Clan/Encyclopedia.
3. Save, exit and reload, verify stats/traits/relations are unchanged, no extra relatives or duplicate grants.
4. Advance a younger child's age through a milestone in a disposable test and check `cu_family_upbringing_milestone` is logged exactly once even after reload. Confirm expected native skill/trait change and original child state/residence.
5. Test Natural and Strained presets in separate new campaigns, verify differences are reproducible only as choices, not identical clones.
6. Review actual production DLL hash. A compiled/packaged CI pass is not a completed in-game release.

## Improving modding accuracy

- Use the user's **actual game binary's** assembly API metadata alongside pinned reference assemblies. The v0.50 `EventManager.MousePosition` runtime mismatch proved compilation alone cannot establish binary compatibility.
- Keep each patch on a narrow, reviewable feature branch with one end-to-end failure case and an automated source contract. Preserve the user-verified v0.51 age controls.
- Test in layers: pure native-independent policy rules → pinned .NET compilation → module installation hash → actual mouse and game state → save/reload.
- Collect a single latest-session ZIP with game module versions, DLL SHA-256, event logs and bounded screenshots. Compare requested and actual values for every new hero.
- Treat static/simulation passes as preflight only. Advance to the next creator feature only after explicit user playthrough evidence.

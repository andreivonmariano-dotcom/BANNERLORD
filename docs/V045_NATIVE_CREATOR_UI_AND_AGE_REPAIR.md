# Calradia Unified v0.45 | Screenshot-driven UI and age repair

**Target:** Mount & Blade II: Bannerlord PC v1.5.7.125802. **Source branch:** `feature/v045-native-visual-polish-age-guidance`. **State:** Compiled and static-test candidate. Actual in-game look and button hit zones require fresh observation.

## Player-reported evidence (November 19, 2026)

Screenshots of the v0.44 test run demonstrated that the full-screen CU-guided World, Culture, Stats and Household pages were stark navy blue, did not resemble the game's original dark stone/wood parchment UI, and suffered crowded / overlapping text. Game-owned Narrative, Banner, Clan, Review and Difficulty stages had a redundant CU header over native titles. The right-docked FaceGen trial showed an empty black scene region in the supplied image. The stats editor did not clearly distinguish skill levels from focus points, so the Focus limit of 5 looked like a skill cap. Starting children asked for impossible ages and rejected them only at final validation. The player requested a year-by-year **age slider**, not ten-year jumps.

## Repair implemented

1. **Warm native-inspired visuals:** `CUGuidedCreator.xml`, `CUNativeStatsEditor.xml`, `CUNativeStatsEditorSafe.xml` and `CUNativeCultureChooser.xml` now use dark leather/stone, brass and parchment colors instead of blue. Every custom TextWidget receives a measured `Brush.FontSize` value, with subdued descriptive text. Culture choices present native culture names only, not overlapping raw IDs.
2. **Better spacing:** the guided question/value and selection actions share a responsive center area with restrained typography and a brass divider. Stats rows are condensed to two non-overlapping text lines, background effects get shorter notes, and footer actions have concise labels. No duplicate `OPTIONAL CHOICES` sidebar header.
3. **Native screens remain unobscured:** v0.44's CU top strip and optional rail over Narrative, Banner, Clan, Review and Difficulty are now disabled, and native position rewriting is suspended with it. This preserves Bannerlord's already fitting stone/wood title and controls without rendering a second, colliding CU title. Native in-place button coloring can still be restored with F10.
4. **Actual 3D FaceGen:** the user screenshot of the trial right dock showed an empty black pane. The active guided start now defaults `NativeFaceDockTrialEnabled=false`, returning to the original native face scene and camera. F9 trial logic stays in the code for engineering use, but it is not part of the new player-facing default. Debug labels on FaceGen are hidden.
5. **Skills are not limited to 5:** the actual `Skill.*` range remains 0 to **330**, with 10-level increments or the exact-value control. `Focus.*` legitimately ranges 0 to **5**. The visible row text now distinguishes `Skill: Riding` from `Focus: Riding`, with distinct range explanations. `Unrestricted` bypasses the 30-point budget but retains valid native game ranges.
6. **Exact player age:** a new first step in the existing post-story Stats creator uses a native `SliderWidget` for **18–80 years, one-year increments**. It binds to `CUNativeStatsVM.PlayerAge`, shows the exact selected year and offers -1/+1 year buttons and `Keep native age`. The game-owned native age story step still decides its real skill/attribute effects; confirming applies the chosen exact birthday to the actual `Hero.MainHero` using `SetBirthDay(CampaignTime.YearsFromNow(-age))` and saves profile. A failure restores the previous birth date. If the pinned Gauntlet Slider prefab fails to load, the same step falls back to `CUNativeStatsEditorSafe.xml` with one-year buttons.
7. **Parent-aware child ages:** the post-clan household creator calculates the valid child-age ceiling from the **younger of the actual player and selected spouse**, minus 16 years, clamped at 55. The field hint shows that limit and both ages. The +/- controls refuse to go beyond it, exact entry rejects out-of-range values immediately, and children older than the new ceiling are clamped when an earlier parent age changes. The underlying family validation remains game-owned/phase-9 safe.

## Safety, known limits and acceptance

The new player age is committed after the native origin narrative, so the Bannerlord age-choice narrative effects are preserved. This is **not a replacement for the original engine-owned age choice** or a guarantee that an exact birth date works with every other mod's age-dependent mechanics. The first age step is in Chapter II between original youth/adulthood and optional custom stats.

The PNGs provided are **evidence of old v0.44 visual defects**, not proof that v0.45 has been rendered successfully. Source / XML verification and the pinned Windows compiler cannot establish new font fidelity, slider dragging, hit boxes, original FaceGen camera rendering, or clipping at specific screen resolutions. Live acceptance must check these at 1366x768, 1650x927, 1920x1080 and ultrawide. Check native culture selection, FaceGen camera, background choices, exact age and birthday at final review, Skill >5 (e.g., 60), Focus=5 and refusal to increase to6, parent 30/spouse25 -> child max9, parent40/spouse50 -> max24, F10 native brush restoration, pregame role/kingdom, final map, family/home, save/reload.

**Never claim pixel-identical native prefabs or a fully verified playable release from static CI.** v0.45 is a focused usability repair, not an overhaul of game-owned native widgets or an unsupported direct-to-map bypass.

# Mandatory retention and retrieval
1. Before development read live comprehensive Google Doc, AGENTS.md, PROJECT_INSTRUCTIONS.md, active production PR/branch and current handoff/CI. Resolve lab/native-engine-research separately. Read INDEX.md, CATALOG.csv, Handoff/CURRENT.md, Failures/REGISTER.csv and relevant actual records. Record consulted IDs and immutable revisions. If unavailable, report blocker before affected work; never substitute chat recollection.
2. Revalidate installed game fingerprints, provider version and ownership. Mark invalidated records stale or superseded; retain history. Inspect actual relevant implementation before design.
3. Evidence levels: UNKNOWN/PROPOSED, METADATA (signatures), CALL_EDGES (selected static references), SOURCE_STUDIED (pinned external source), COMPILED (actual artifact/tests), NATIVE_OBSERVED (specific version/profile and measured outcome), PLAYER_ACCEPTED (human repeated-use critique), REGRESSION_VERIFIED (negative cases, reload, control/full-stack). Record BLOCKED, NOT_RUN and FAILED explicitly. No automatic promotion.
4. Every milestone updates relevant technical records, catalog, cumulative learning, failures when applicable, evidence, matrix and handoff. Use stable IDs, date, exact version/hash/source, verified contract, reproducible method, actual result, limitations, provider ownership, correction and next test. Append corrections, never erase failed attempts. Keep private logs/screenshots/saves locally and publish only sanitized conclusions; no game binaries, full decompiled bodies, unapproved external code or credentials.
5. Research -> design -> isolated prototype -> native test -> player critique -> integration -> regression. Each feature needs real situation, motivation, distinct decisions, supported action and observable outcome. No decorative ranks, repetitive scripted loops, debug prose or duplicate provider systems. Production stays frozen until useful native-tested, player-accepted prototype; install, merge and release need separate authorization and gates.
Project instructions route to the handbook and GitHub; GitHub retains technical knowledge; local lab retains evidence/artifacts. No automatic model retraining or guaranteed retrieval: explicitly read actual records.

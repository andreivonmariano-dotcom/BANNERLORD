# CU | Six-system game design library

25 November 2026. The six documents are the current design contracts subordinate to PROJECT_INSTRUCTIONS.md and CU_MASTER_ROADMAP.md. They distinguish compiled source, observed native state, proposed expansion and retired features. Each includes player loop, mechanics, UI, state, ownership, failure boundaries, exact mapped feature IDs and native acceptance cases. Do not treat a proposed feature as implemented. Shared technical/legacy contracts belong in the audit and tracker, not a seventh gameplay system.

- [S1 Starting Life](design/S1_STARTING_LIFE.md): 25 mapped feature/subfeature rows.
- [S2 Family and Dynasty](design/S2_FAMILY_AND_DYNASTY.md): 20 mapped feature/subfeature rows.
- [S3 Household and Retainers](design/S3_HOUSEHOLD_AND_RETAINERS.md): 16 mapped feature/subfeature rows.
- [S4 Living Relationships](design/S4_LIVING_RELATIONSHIPS.md): 27 mapped feature/subfeature rows.
- [S5 Career and Sworn Service](design/S5_CAREER_AND_SWORN_SERVICE.md): 6 mapped feature/subfeature rows.
- [S6 Personal Chronicle](design/S6_PERSONAL_CHRONICLE.md): 8 mapped feature/subfeature rows.

Integration: S1 establishes the actual native person and starting state. S2 maintains real kinship context. S3 exposes feasible native responsibilities. S4 surfaces relevant concerns and explicit choices. S5 witnesses obligations and native career changes. S6 reads confirmed facts, not instructions to mutate the campaign. The six systems share four access points, no independent menu for every feature. External owners remain authoritative. Design changes require traceable source and acceptance updates. R1/R2 precede further expansion except narrow authorized fixes. No calendar promises.
